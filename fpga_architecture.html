FPGA 工作原理 · 架构图解

从硅片上的一个 SRAM 位，到一个跑在 148.5 MHz 上的 1080p60 视频通路

示例器件：紫光同创 Logos2 系列 PG2L100H-6IFBG676（盘古100Pro+ 开发板）· 工具链 Pango Design Suite

FPGA 这个词本身是个缩写，全称 Field Programmable Gate Array，字段可编程门阵列。这三个词就是全部答案的骨架：

Field现场可编程
出厂后由用户改
Programmable可编程
功能由配置位决定
Gate Array门阵列
规则排布的单元阵列

要真正理解它，需要把这句话拆成三个可编程层，再逐层放大到硅片。下面按从整块芯片 → 到单个配置位的顺序展开，最后再回到"写一段 Verilog 之后芯片里到底发生了什么"。

全文主线 FPGA 里没有"指令"。它没有取指、译码、执行这些环节，也没有 CPU 那种"一条一条按顺序跑"的流程。芯片里存在的是空间上的结构：几万个查找表、几万个触发器、一张可编程的开关网络，以及遍布全芯片的配置存储位。你写的 Verilog 经过工具链，最终变成的是一份"哪些开关闭合、每个查找表存什么真值表"的位流文件。上电时把这份位流灌进去，芯片就"变成"你要的电路。断电，配置位丢失，电路消失。

图 1 · FPGA 芯片平面布局（列式架构）。所有现代 FPGA 都采用这种"列式"布局：中间是规则排布的逻辑阵列，存储块（BRAM）和运算块（APM/DSP）以竖直列的形式嵌在阵列中间，外围一圈是 IO Bank，硬核集中在芯片一侧。
这块板子的 Bank 与电平：左侧 L3 / L4 / L5 为 3.3 V；L6 / L7 的电平由板上跳线选择（ADJ_3V3 / 2V5 / 1V8，接 OV5640 这类 1.8 V 器件前必须改跳线）；右侧 R4 / R5 为 1.5 V，专供 DDR3（VDDQ = 1.5 V）。IO 的电平标准是按 Bank 配置的，一个 Bank 内的所有引脚通常共享同一套 IO 供电，所以"哪个外设接在哪个 Bank"是硬件设计阶段就要定死的事。

为什么是列，不是随便撒 BRAM 和 APM 是较大的矩形硬块，如果随机撒在逻辑阵列里，布线资源会被切得支离破碎。做成整列贯穿之后，它们共享同一条纵向布线通道，逻辑阵列也保持完整。这个布局选择带来一个你必须知道的后果：资源分布是不均匀的。如果你的设计要用 100 个乘法器，而它们全都要连到某一小片区域，工具就必须把那片区域的逻辑挪走，甚至报"资源拥塞"。这就是为什么 FPGA 的"布局布线"是个 NP-hard 的启发式问题，而不是简单分配。

2CLM：逻辑阵列的最小积木

第二层放大：阵列里的一个"格子"里面有什么。

CLM（Configurable Logic Module）16,650 个，铺满整个逻辑阵列
4 × LUT6 — 每个可实现任意 6 输入 1 输出组合逻辑也可拆成两个 5 输入 LUT 使用，提高利用率
8 × 触发器 FF — 每个 LUT 配 2 个可配置为 D 触发器 / 锁存器，可带置位复位与时钟使能

宽 MUX（F7 / F8） — 把 4 个 LUT 组合成 7 或 8 输入函数以及把 LUT 当分布式 RAM / ROM 用的通路

把这些拼起来，一个 CLM 的结构是：

图 2 · CLM 内部结构。4 个 6 输入 LUT 负责组合逻辑，8 个 FF 负责存状态，进位链负责快速加法，宽 MUX 负责把多个 LUT 拼成更宽的函数。信号从左边进、右边出，全部经过可编程互联。注意 FF 的输入既可以接 LUT 的输出，也可以旁路 LUT 直接接互联线。

关键比例：LUT : FF = 1 : 2 这块芯片是 66,600 个 LUT6 配 133,200 个 FF。触发器比查找表还多一倍——这个比例不是巧合，它是综合工具期望的平均值：一个查找表的输出，通常有一半的概率需要被打一拍（寄存）。当你写的设计里寄存器用量远超这个比例时，工具会开始用 LUT 硬搭寄存器，效率急剧下降；反之如果全是组合逻辑、几乎没有寄存器，那你的设计很可能上不了高频。这个比例本身就是一条设计经验。

3LUT：可编程的物理根源

第三层放大：一个"6 输入任意逻辑"的盒子，里面到底是什么。这是整篇文档最核心的一节。

先说结论：一个 N 输入查找表，物理上就是一块 2N × 1 bit 的 SRAM，加一个 2N 选 1 的多路选择器。 输入信号接多路选择器的选择端（相当于 SRAM 的地址线），SRAM 里存的内容就是真值表，多路选择器的输出就是函数结果。

下图是一个 4 输入查找表（为看清结构画成 16 行；这块芯片里是 6 输入、64 行）：

图 3 · 查找表的物理实现。图中 SRAM 的内容是"A 与 B 相与"这个函数的真值表（A 为最低位、B 为次低位，所以只有地址 3、7、11、15 处为 1）。C 和 D 在这个函数里是无关项，工具会任意填值。函数不同，变的只是这 16 个 SRAM 位的内容——硅片结构完全不变。

这就是"可编程"的物理根源 一个 4 输入函数共有 216 = 65,536 种可能。因为查找表把全部 16 种输入组合的结果都存下来了，所以它不关心你要实现的是什么函数——任意 4 输入 1 输出的组合逻辑，都能用它实现。这块芯片用的是 6 输入查找表，264 种可能，实践中天文数字级别的逻辑函数都能覆盖。

对比一下 ASIC（专用芯片）：ASIC 用晶体管直接搭出那个逻辑门，功能焊死在版图里，改不了。FPGA 用一个"万能盒子"加一份可写的答案表，牺牲面积和速度（一个 4 输入与门在 ASIC 里只要几个晶体管，在 FPGA 里要占一整个查找表加布线），换来的是出厂后还能改。整个 FPGA 产业就是建立在这笔交易上的。

3.1 那 6 输入 LUT 怎么实现更复杂的逻辑？

如果一个函数有 10 个输入怎么办？工具会把它拆成多个查找表，用宽 MUX 拼接，或者用多级。代价是级数增加 → 延迟增加。这直接引出了后面第 7 节的时序问题。而像加法这种高频操作，厂商专门做了进位链来加速，避免逐级串接。

4可编程互联：芯片的神经系统

第四层：查找表之间怎么连起来。这一层往往被忽略，但它才是 FPGA 性能的真正瓶颈。

光有查找表没用，它们得能互相连接。FPGA 的做法是在逻辑阵列中预留纵向和横向的布线通道，通道之间用开关盒（Switch Box, SB）交汇，逻辑单元接入通道的地方用连接盒（Connection Box, CB），通道里的每一条可能的连接都由一个可编程互连点（PIP, Programmable Interconnect Point）控制通断。

图 4 · 可编程互联网络。红色高亮是一条信号从某个 CLM 出发、经过连接盒进入横向通道、穿过开关盒转向纵向通道、再穿过另一个开关盒转向横向通道、最后经连接盒进入目标 CLM 的完整路径。右上是其中一个 PIP 的放大：它的全部"智能"就是一个配置位控制的开关。

这条通路解释了三件事 1. 为什么布线延迟常常比逻辑延迟大。 一次 LUT 运算的延迟是固定的、很短的；但一次跨区域的信号传输要穿过好几级开关盒，每过一级就是一个晶体管开关的导通电阻加上一段导线电容。布线延迟在很多设计里能占到整条路径的 50%~70%。

2. 为什么"同样的代码换个器件要重跑时序"。 换器件意味着换阵列规模、换通道数量、换开关盒结构。工具重新布局布线后，每条路径经过的开关盒数量全变了，延迟自然全变。这在 STM32 世界里不存在——你写 C 代码换一颗 F1 到 F4，指令周期变了，但不会有"布线延迟"这种概念。

3. 为什么布局布线要跑那么久。 工具要在"把哪些 LUT 放在一起"和"怎么把它们连起来"之间反复权衡，因为放得越近、连线越短、能跑的时钟越快，但资源又必须均匀分布才放得下。这是一个 NP-hard 问题，只能靠启发式算法反复迭代，所以跑几十分钟到几小时都正常，而且同一份代码跑两次，结果可能不同。

5配置存储：为什么断电就没了

第五层：这些"配置位"到底存在哪，怎么进去的。

上面已经出现了三类配置位，它们实际上是同一批 SRAM 单元：

查找表内容每个 LUT6 存 64 bit
决定它实现什么函数
多路选择器选择端决定信号走哪条路
包括宽 MUX 和输出选择
互连点通断每个 PIP 1 bit
数量最多的一类
BRAM 初值上电时存储块的初始内容
IO 电平标准LVCMOS / LVDS / SSTL
驱动强度、上下拉

把这些位全部按顺序打包，就是位流（bitstream）文件。它包含的信息量有多大？粗略估一下：光查找表内容就是 66,600 × 64 bit ≈ 4.3 Mbit，互连点的数量通常是查找表数量的几十倍，每个 1 bit。整颗芯片的位流规模在几十兆比特量级。这就是为什么 FPGA 的配置文件动辄几 MB 到几十 MB。

5.1 两条配置路径

路径 A · JTAG 直下（易失）

电脑上的 PDS生成 .sbit 位流
下载器（USB）转成 JTAG 时序
JTAG TAP 控制器芯片内的状态机
写进全部配置 SRAM电路立即生效

用途：调试。改一行代码，重新综合布线，几十秒到几分钟后再下进去看现象。缺点是一断电全丢，下次上电芯片是一片空白，什么都不做。

路径 B · 固化到 Flash（非易失）

PDS 生成 .sbit / .bin面向 Flash 的格式
JTAG 间接写入板载 QSPI Flash
断电 → 重新上电Flash 内容还在
配置控制器自动读取SPI 时序，把位流搬进 SRAM
电路自动恢复不需要电脑参与

用途：交付。板子单独上电就能跑，这是比赛现场演示必须做的事。这一步叫"固化"或"烧录到 Flash"。

这个机制决定了你的开发节奏 每次改代码都要重新走一遍"综合 → 布局 → 布线 → 生成位流 → 下载"，其中布局布线是大头。所以 FPGA 开发和写 Python 完全不是一个节奏：你的迭代周期是分钟级的，不是秒级的。这也是为什么 FPGA 工程师会花大量时间在仿真上——在电脑里把逻辑验证对了再上板，比反复烧板子快得多。

7时序：FPGA 开发真正的门槛

这一节是 FPGA 和单片机最本质的分界线，也是绝大多数新手卡住的地方。

在单片机里，你写 a = b + c;，编译器生成几条指令，CPU 一条一条执行。你几乎不用考虑"信号从 b 传到加法器要多久"。在 FPGA 里，这条语句会变成一片真实的硬件：一段导线、一个加法器、一段导线。 信号在导线上传播需要时间，加法器算出结果需要时间。如果时钟太快，信号还没稳定下来，下一个时钟沿就来了，寄存器就会采到错误的值。

图 5 · 寄存器到寄存器的时序路径。一个时钟周期内，数据必须从 FF1 的 Q 出发，穿过组合逻辑，在下一个时钟沿到来之前稳定在 FF2 的 D 端并保持 Tsetup 那么久。

时钟周期 Tclk ≥ Tco + T逻辑 + T布线 + Tsetup + T时钟偏斜

这条不等式就是 FPGA 里"能跑多快"的全部答案。你能达到的最高时钟频率，由你设计里最长的那条组合逻辑链决定。 这解释了几个很实际的现象：

为什么你写的同一段 Verilog，在别人的板子上能跑 200 MHz，在你的板子上只能跑 120 MHz？因为器件不同、布线不同，T布线 不同。为什么你在仿真里完美运行的逻辑，上板之后结果偶尔出错？因为仿真默认是"零延迟"的，它根本不检查这条不等式。仿真通过只说明功能对，不代表时序对。

7.1 解决手段：流水线

既然问题出在组合逻辑链太长，那就在中间插一级寄存器把它切断。这是 FPGA 设计中最重要的优化手法。

优化前：一条长链

FF
组合逻辑 A + B + C + D（全部串在一起）
FF

路径延迟 = 四级逻辑之和 + 布线。
最高频率低（假设只能跑 80 MHz）。
吞吐：每周期出 1 个结果。

优化后：切两段

FF
逻辑 A + B
FF
逻辑 C + D
FF

最长路径减半，频率可以翻倍（≈160 MHz）。
代价：多了 1 个周期延迟（Latency）。
吞吐：仍然是每周期 1 个结果（只是晚一拍出来）。

为什么流水线在视频处理里几乎总是划算的 视频流是连续不断的：每帧 1920×1080 个像素，源源不断地来。流水线增加的是"延迟"（第一个像素出来得晚几拍），但"吞吐率"（每秒能处理多少像素）不变甚至更高。对视频来说延迟几拍完全可以忽略，而吞吐率直接决定你能不能实时处理 1080p60。这个"用延迟换频率"的思路，是你后面做图像管线时的核心设计手法。

8时钟网络：为什么时钟要特殊对待

时序里有一项叫"时钟偏斜"，这一节说它是怎么来的、怎么控制的。

时钟要同时驱动几万个触发器。如果时钟信号走普通布线资源，到达不同触发器的时间会差很多，这个差就叫时钟偏斜（Clock Skew）。偏斜会直接吃掉你的时序余量。所以 FPGA 里有一套专用的全局时钟网络：它是专门的低偏斜树形结构，从芯片中心向外呈树枝状展开，保证各个分支到叶节点的延迟几乎相同。

图 6 · 时钟网络。外部晶振 → PLL 倍频 → 全局时钟缓冲 → 专用时钟树 → 各触发器。整条路径都走专用资源，不占用普通布线通道。

对你这块板子的具体含义 盘古100Pro+ 板上的晶振是 27 MHz 单端有源晶振，接到 FPGA 全局时钟引脚 D18；另有一路 125 MHz 差分有源晶振接到 N3/N2，用作 DDR3 的参考时钟。

而 1080p60 视频所需的像素时钟是 148.5 MHz——27 和 148.5 不是整数倍关系（148.5 / 27 = 5.5），所以你必须用 PLL 做 11 倍频再 2 分频，或者用 PLL 的小数分频能力。这个"148.5 MHz 从 27 MHz 来"的推导，是你后面写 HDMI 输出模块时的第一个具体任务。PLL 的输出不能直接接普通 IO，必须经过全局时钟缓冲（BUFG）才能驱动整个阵列，这是新手常犯的一个错误。

9硬核与软核：同一颗芯片上的两种"电路"

这颗芯片上不是所有东西都是"可编程"的。有一部分是出厂就焊死的专用电路。

硬核（Hard IP）

用专门的硅片电路实现的固定功能模块。出厂就存在，不能被改造成别的用途，但性能高、功耗低、不占用 LUT/FF 资源。

PCIe Gen2 ×4硬化的 PCIe 协议控制器
HSST ×8 · 6.6 Gbps高速串行收发器（SerDes）
BRAM · APM存储块与乘法器阵列
PLL · ADC · AES时钟、模拟、加密
HMIC 硬核 IODDR3 的物理层接口

软核（Soft IP）

用 LUT 和 FF 搭出来的功能模块。本质上就是你写的（或厂商提供的）Verilog 代码，经过综合布局布线后占用可编程资源。

UART · SPI · I²C 控制器几行到几十行代码的事
DDR3 控制器这块芯片上用的是 soft HRIO DDR IP，占逻辑资源
图像处理管线缩放、色彩空间转换、边缘检测
RISC-V 软核 CPU用逻辑资源搭出一个处理器
你比赛要写的全部逻辑这是你的主战场
一个容易混淆的点 硬核和软核的界线不是"厂商提供"还是"自己写"。厂商也会提供软核 IP（比如 IP Compiler 里生成的 FIFO、PLL 控制器、DDR3 控制器），它们是参数化的 Verilog 代码，照样占你的 LUT 和 BRAM。

判断方法很简单：看它占不占逻辑资源。占，就是软核；不占（或者只占很少的接口逻辑），就是硬核。

这个区分有很实际的后果：硬核是不可移植的。你在这块芯片上用 PCIe 硬核，换到别的厂商的芯片上，那个 IP 就完全不能用了，必须换成对方对应的硬核或软核实现。而你自己写的图像处理算法，只要不用厂商原语，换芯片基本能直接搬。这也是为什么"哪些代码要写得尽量通用"是 FPGA 工程里一个真实的架构决策。

10全链路：你写的一行 Verilog，最后变成了什么

把前面九节串成一条完整的因果链。

① 你写：always @(posedge clk) if (en) q <= a & b;这是一段"行为描述"，它描述的是一块硬件，不是一个执行步骤
② 综合器理解："需要一个二输入与门，输出接一个带使能的 D 触发器，都挂在 clk 上"输出：门级网表
③ 映射：与门 → 一个 LUT6，其 64 个 SRAM 位被写成"只有 a=1 且 b=1 时输出 1"的真值表触发器 → 该 CLM 里的一个 FF
④ 布局布线：在 16,650 个 CLM 里挑一个位置，并决定 a、b、clk、q 这四根信号各走哪条通道、哪些 PIP 闭合输出：一条具体的物理路径
⑤ 位流生成：那个 LUT 的 64 个配置位、那个 FF 的配置位、路径上所有 PIP 的状态位，一起被写进 .sbit 文件输出：一个几十兆比特量级的二进制文件
⑥ 配置：位流被逐位写进全芯片的配置 SRAM写入的瞬间，那块"万能硬件"就变成了你要的电路
⑦ 电路开始工作：每个时钟沿，那个 FF 采样一次 LUT 的输出同时，还有几万个其他 FF 也在同一个时钟沿上各自工作
回到最初的那个问题：FPGA 和单片机到底差在哪 单片机是一个聪明的人，按顺序一件一件做事。你写的 C 代码是时间上的步骤，处理器依次执行。频率再高，同一时刻也只有一个（或几个）运算在做。

FPGA 是几万个简单的人，每人负责一小块，同时工作。你写的 Verilog 描述的是空间上的结构，工具把它铺到硅片上。所以"66,600 个 LUT"意味着理论上可以同时做六万多个逻辑运算。

这带来两个直接后果，也是你后面做 ADAS 项目时会反复体会到的：
· 视频处理天然适合 FPGA。 每个像素的处理互相独立，可以几百路并行同时算，这是"同时"的用武之地。
· 复杂控制逻辑不适合 FPGA。 状态多、分支多、要跑协议栈、要调度任务——这种"一件事接一件事"的活儿，CPU 比 FPGA 高效得多。所以真正成熟的架构是软硬协同：CPU 做调度和决策，FPGA 做确定性的高速数据通路。你这块板子上"泰山派 RK3566 + 盘古100Pro+"的组合，本质上就是这个分工。

11附：这块芯片的可编程资源分布直觉

把抽象数字换成能感知的规模。

你能想到的东西大概消耗多少资源依据
一个 UART 收发器约 100~200 个 LUT + 100 个 FF波特率计数、位计数、状态机
一个 1080p 的行缓存（1920 像素 × 24 bit）约 1.3 块 BRAM1920 × 24 = 46,080 bit，一块 BRAM 是 36 Kb
一个完整的 1080p 帧缓存（24 bit 色深）约 1,490 块 BRAM
远超片上 155 块		1920 × 1080 × 24 = 49.8 Mbit。所以帧缓存必须放 DDR3，片上只能放行缓存
一个 3×3 卷积窗口的 Sobel 边缘检测约 2 条行缓存 + 几百个 LUT需要缓存两行才能形成 3×3 窗口
一个 25×18 乘法1 个 APM，不占 LUT硬核乘法器
一个 RISC-V 软核（如 PicoRV32）约 2,000~3,000 个 LUT占整颗芯片的 3%~5%
这条估算的用途 表格里"1080p 帧缓存要 1,490 块 BRAM、而芯片只有 155 块"这一行，是你在做方案设计时最该先算的一笔账。它直接决定了你的图像处理架构必须是流式的（line buffer 加流水线），而不是帧式的（整帧缓存再处理）。 这个约束会一路影响你的算法选型、模块划分和时序设计。比赛方案里如果出现"缓存整帧再做处理"的表述，评委一眼就能看出设计者没算过这笔账。
