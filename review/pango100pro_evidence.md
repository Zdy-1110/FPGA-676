## 0. 结论与证据边界

**本次不能签署“卡边引脚及双独立电源互连已验证安全”的结论。** 已核实的是资料中的明确表述和工程中的实际配置；二进制底板 SCH 未取得可靠的连通图/网表，未找到核心板独立完整原理图。因此真实 PCIe 卡边接触号、卡边电源与外接 12 V 的关系以及 PRSNT/WAKE 实现仍未闭环。

优先级最高的发现：

1. **REFCLK 球位冲突**：S1 的 PCIe 表写 P=F13、N=E13；S2 的板级约束截图以及两套示例的板级 FDC 均使用 P=F11、N=E11。S1 的另一个章节又把 F13/E13 分配给底板 U4 的 125 MHz 时钟。工程配置可以确认；物理卡边到底连到哪一组，不能仅凭这些文字替代原理图证据。
2. **PERST 板级配置是 G24、低有效、3.3 V LVCMOS33 输入**；DMA 压缩包内的 IP 自带 example_design 约束另写 L4，不能把内层模板当作板级约束。
3. **lane reversal 配置冲突**：S2 要求启用；通信测试示例确实启用；DMA 示例的 IDF 与生成 RTL 却关闭。两套示例不是可以无条件混用的同一配置。
4. **PCIe 编号与 HSST 编号反序**：按 S1 两张表交叉核对，手册 PCIE 通道 0 对应 HSST 通道 3，PCIE 通道 3 对应 HSST 通道 0。这里是手册信号编号关系，不是已经核实的卡边 A/B 接触号，也不是反转 P/N 或 TX/RX。
5. **独立供电不是隔离证明**：S1 确认底板输入 +12 V，并由底板给核心板提供 +5 V；但没有取得可读证据证明 PCIe 电源脚与外接 +12 V 已隔离、经二极管 OR-ing 或具备反向阻断。

### 证据使用规则

- “手册确认”：能在指定页的表格/图中直接读出；不等于本次测量了实物或完整追踪了板间连接。
- “工程确认”：能在实际 IDF、FDC、RTL、PDS 中定位到对应内容；不等于焊接版本或已烧录镜像必然相同。
- “连通确认”：需要清晰的完整原理图线段/器件引脚，或经过正确解析的网表端点。本次对卡边与外接 12 V 尚不具备此类证据。
- **二进制中出现网名，绝不作为连通证明。** 未把标准 PCIe 接触号、原理图符号序号、板对板连接器脚号或 FPGA 球位相互替代。
- PDF 页码均为从 1 开始的文件物理页；另列印刷页码以避免页码偏移。

## 2. PCIe 能力、用途及收发方向

### 2.1 能确认的资料与配置

- S1 PDF 41（印刷 37）描述的是 **PCIe x4 插卡形态**，可插入 PC 的 x4 插槽；四通道收发连接 FPGA HSST，单通道最高 5 GT/s，卡槽给板卡提供 100 MHz 参考时钟。
- S2 PDF 187（印刷 180）列明 IP 可选 EP、Legacy EP、Root Port，x1/x2/x4，以及 2.5/5 GT/s；这是 IP 配置能力，不代表当前样例是 RC，也不证明当前实物链路已建立。
- T2 与 D2 的明确 GUI 参数均为 **PCI Express Endpoint、X4、100 MHz、5 GT/s**。结合 S3 PDF 214（印刷 207）“PC 软件驱动作为 RC 端，盘古板为 EP 端”的实验说明，已审查样例按 EP 使用。
- S3 PDF 175（印刷 168）列明 DMA 例程支持 Gen1/Gen2 的 x1、x2、x4 模式；不能由此承诺任意裁减 lane 的中间板都能训练。
- S3 PDF 177（印刷 170）与 T3/D3 一致：`rxp/rxn` 是 FPGA 输入，`txp/txn` 是 FPGA 输出；`ref_clk_p/n` 与 `perst_n` 也是输入。这里的 TX/RX 方向以 **FPGA 板卡为参照**。

因此跨端方向只能在角色与端口定义确认后表达为“对端 TX → FPGA RX、FPGA TX → 对端 RX”，不能把两端相同字符串的 TX 网直接并起来。本报告没有审查另一端。

### 2.3 必须保留的不确定性

- 手册 PCIE 通道号与标准卡边 lane 号是否完全一致，未完成原理图闭环。
- 卡边正反面的 A/B 接触号、P/N 极性、卡边方向、原理图符号的 pin 编号如何对应，均不能用标准表推定成本板的“已验证接触号”。
- x1/x2 降宽时应保留哪组实物触点，及 lane reversal 对该配置的实际效果，尚未验证。
- 样例中的 `NUM_OF_LANES=5'b1` 是内部编码，**不能仅凭这个数字判定为 x1**；当前 X4 的依据是 IDF 的 `Maximum_Link_Width=X4`、RTL 的 `HSST_LANE_NUM=4` 以及四路端口。

## 4. PERST：逻辑、电平配置及模板污染

明确证据：

- S1 PDF 43（印刷 39）：`PCIE_PERST → G24`。
- S1 PDF 32（印刷 28）核心板 J3 表：J3.9 → `L4_G3_18P_A22` → G24。此处证明手册中核心板侧对应脚，不证明卡边对应接触号。
- S2 PDF 193（印刷 186）图 13.3-8：`perst_n` 为输入，G24、BANKL4、VCCIO=3.3、LVCMOS33。
- T1 行 82-85 与 D1 行 93-96：输入、G24、3.3、LVCMOS33。
- S3 PDF 177（印刷 170）明确写：`perst_n` 为输入，**低有效、来自插槽 PERST#**；与调试用 `button_rst_n` 分开。

```tcl
# T1 行 82-85；D1 行 93-96 同样配置
define_attribute {p:perst_n} {PAP_IO_DIRECTION} {Input}
define_attribute {p:perst_n} {PAP_IO_LOC} {G24}
define_attribute {p:perst_n} {PAP_IO_VCCIO} {3.3}
define_attribute {p:perst_n} {PAP_IO_STANDARD} {LVCMOS33}
```

但 D4 行 82-85 的 **IP 自带内层 example_design** 写 `PAP_IO_LOC=L4`，且是生效行。D5 行 304-305 选择的是外层 D1。因此：

- 可确认该 DMA 板级工程选用 G24 的外层 FDC；不能说整个 RAR 中所有模板都适配此开发板。
- `L4` 是另一 FPGA 球位，不是 BANKL4 的缩写；不得因为截图标 BANKL4 就接受 `LOC=L4`。
- 不能由工程的 3.3 V 输入配置推断卡边上没有电平转换、输入 5 V 安全、另一端 1.8 V 可以直接驱动，或 FPGA 断电时不会通过输入反向供电。
- 实物的上拉电压/阻值、串联器件、保护器件、掉电容限及卡边 PERST 接触号均未核实。

### 10.4 给 REV_B 的电源域 / 缓冲边界（推导要求，不是 TI 选型结论）

- 正电源跨板隔离与 PERST 侧带掉电安全是不同事项。全切 +12 V/+3.3 V/辅助电源不能证明 G24 安全；GND 和连续信号参考地不属于要切断的正电源轨。
- 若选择具备适当掉电保护的开漏/开集缓冲，上拉应引用 **G24 所在接收域实际有效的本地 3.3 V/VCCIO**，不应为了上拉重新把另一板的 3.3 V 跨排线接进来。
- 目前不能确认 PCIe 金手指 3.3 V 是上述本地接收域的取电点。不要默认用它作缓冲 VCC/上拉电源；应先确认正确触点网络，或使用另外已验证的本地供电点。
- 如后续发现已有外部上拉，先核对位号/阻值/电源域再决定是否装 REV_B 额外上拉；不能凭 UNKNOWN 删掉选位，也不要在未知已有电阻时盲目并加强上拉。
- **Ioff / 输出高阻不等于复位保持有效。** 例如缓冲由 RC 供电，RC 断电后输出高阻，而 Pango 上拉仍有效，PERST 就可能被拉高、即释放复位。缓冲供电域、未供电输入默认值和 RC 失效时的输出态必须共同定义。
- 若缓冲由 Pango 接收域供电，则“RC 已供电、Pango 未供电”要验证输入和输出的实际掉电容限；若由 RC 供电，则“RC 未供电、Pango 已供电”要处理上拉是否释放复位。不能只验证一个方向。
- 正常释放复位还要服从 FPGA 实际加载、接收域电源和参考时钟条件；本次没有验证具体时序数值或最终镜像。

没有查阅 SN74LVC1G07 或其他 TI 器件资料，不对该型号的电气能力作结论。**当前不应把直通当成已验证安全默认；保留适当掉电隔离的缓冲路径与接收端上拉选位是保守候选，但具体型号、供电侧和默认复位逻辑仍由你完成器件级验证。**
