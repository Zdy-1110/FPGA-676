## 0. 结论摘要

1. **一个事实源，两份母稿，四种渲染产物**：`docs/技术文档_最终稿.md` 是唯一完整事实母稿；`docs/提交文档_初稿.md` 是评审版派生母稿，只允许删减、重排和改写，不允许新增数字或结论。两份母稿各自生成 DOCX/PDF，共四种渲染产物。
2. **主文档按“评委评分维度”分五部分**：总览与符合性 → 系统架构设计 → 资源占用与性能测试 → 测试方式与现场演示 → 工程规范与交付；共 **12 章 + 4 个附录**。
3. **评审版正文目标 29–36 页，附录 9–10 页，合计 38–46 页**；完整版 65–75 页，作为支撑材料随源码包或附件提交。
4. **提交前必须重建并核对**：现有 DOCX/PDF 均早于 Markdown 源；文档内页数口径已根据重建后的 PDF 统一更新为：完整版实测 77 页、评审版实测 29 页。
5. **赛题的四个分析报告硬指标各有独立落点**：系统架构设计（第 2–3 章）、软硬协同数据流分析（第 4 章）、资源占用（第 6 章）、性能测试报告（第 7 章）；代码规范独立成第 9 章。

### 0.1 方案取舍

| 方案 | 优点 | 风险 | 结论 |
| :--- | :--- | :--- | :--- |
| 单一大文档（70+ 页） | 一次提交、无版本分叉 | 评委阅读负担重，核心亮点容易被淹没 | 不采用 |
| 只交评审版（20–30 页） | 紧凑、易读 | 代码规范、复现细节不足，难支撑“完整技术文档” | 不采用 |
| **评审版 + 完整版（本方案）** | 5 分钟能看懂，30 分钟能复核 | 两版可能漂移 | **采用**；用单一事实源 + 派生规则约束 |

### 2.3 单一事实源规则

1. **数字只认三处**：`log/board_20261101/FACTS.md`、带日期的 evidence 日志、代码/约束文件的实际行号。
2. **改动顺序**：证据/FACTS → 完整版母稿 → 评审版派生稿 → 重建两份 PDF。禁止只在评审版里改数字。
3. **评审版不新增结论**：评审版出现的新结论，必须先补进完整版；否则删除或降级为“待验证”。
4. **每个量化指标带出处**：正文内联 `（来源：path:line）`，或统一指向附录 D 的证据索引。
5. **一份文档只讲一个版本**：提交口径固定为 cam18（`0x838 = 0x20261101`）；cam17（`0x20261029`）只作为 Flash 回退版本出现，且必须标注“回退”。

## 六、写作与一致性规则

### 6.1 版本与事实口径

- 提交口径固定为 **cam18**：位流 `D:/pango_work/quad/out/quad_cam18.sbit`，版本寄存器 `0x838 = 0x20261101`。
- cam17（`0x20261029`）只作为 Flash 回退版本出现，且必须标注“回退”，不得与 cam18 指标混写。
- 所有性能数字必须能追溯到 `log/board_20261101/FACTS.md`、带日期的 evidence 日志或代码行号。
- 禁止把“模型级/仿真级/门级/板级”的数据混在同一个“实测”口径下；每张表必须写清测量层级。

### 6.2 状态用语

| 用语 | 含义 | 使用条件 |
| :--- | :--- | :--- |
| **完成** | 已在板端或全量数据集上验证，且有证据 | 有日志/回读/复现命令 |
| **部分完成** | 主体功能可用，但存在明确未验证项 | 必须同时写出未验证项 |
| **未实现** | 仅有方案或离线原型 | 不得写成“完成” |
| **待录制/待上板/待标定** | 交付物或验证动作尚未完成 | 放入第 10 章或第 12 章检查清单 |

### 6.3 图表与编号

- 图/表统一“章号-序号”：图 2-1、表 7-2；附录用 A-1、B-1。
- 每张图表必须在正文出现引导句，禁止悬空图表。
- 表格首行跨页重复；4 列以上表格用 9–10 pt 字号（构建脚本已支持 `--compact`）。
- 关键指标表统一列：指标项 / 实测值 / 测量条件 / 证据出处。

### 6.4 语言与禁词

- 统一使用“本系统”“本设计”，避免“我们”与“笔者”混用。
- 禁用无法核实的绝对化表述：首创、业内首次、独创、颠覆、彻底归零、100% 可靠、零风险等。
- 边界说明使用“当前未验证/未实测/未上板”，不用“暂不涉及”淡化。
- 单位统一：MB/s、ms、µs、ns、MHz、GT/s、0x 十六进制、×（不用 x）。

### 6.5 构建与版本记录

- 母稿：Markdown；渲染：`python tools/docs_figs/build_doc.py --md <md> --docx <docx> [--compact]`。
- 每次提交构建后记录：版本号、日期、git commit、位流 MD5、PDF 页数、源码包 SHA256。
- 页数以最终提交的 PDF 为准；本项目用 LibreOffice 转换，DOCX 在 Word 中分页可能相差 1–2 页。
- DOCX/PDF 不纳入人工修改；所有改动回到 Markdown。
