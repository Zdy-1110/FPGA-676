### 镜头 5：赛题测试 (1) 十字路口红绿灯判决 (01:21 - 01:49, 28s)
- **画面内容**：
  - 画面锁定前视主车道测试视频：自车接近十字路口，前方信号灯显示红灯。
  - 屏幕下方叠加的左转、直行、右转三组 24×24 矢量指示箭头实时更新；当前直行车道为红灯，直行箭头呈现鲜红色，状态寄存器 `0x850` 写入 `0x0C`（红灯停）。
  - 模拟驾驶员强行起步（闯红灯）：屏幕四周瞬间爆闪 2Hz 红色警示边框，状态字突变为 `0x10C`，声光告警同步激发。
  - 随后信号灯变绿，自车恢复行驶，屏幕边框红闪解除，直行箭头变为绿色通行（`0x08`）。
- **屏幕叠加字幕**：
  - 行1：红灯禁行直行箭头显红
  - 行2：闯红灯毫秒级全屏爆闪告警
- **物理操作**：
  - 01:23：短按 KEY0（C22）切换自车所在车道至中间直行车道。
  - 01:30：在红灯状态下短按 KEY1（C23，设置 `moving=1`），人为触发闯红灯违规状态。
  - 01:39：信号灯转绿后，再次短按 KEY1（保持 `moving=1`），恢复合规通行。
- **解说词**：纯C语言算法tl_det实现零内存分配的交通灯逐帧识别。当红灯违规行驶时，系统毫秒级触发全屏红色边框爆闪警示。
- **拍摄方式**：HDMI 采集卡直录（全屏） + 手机特写拍摄板载蜂鸣器/告警 LED 联动（画中画叠加）。
- **失败预案**：若现场视频交通灯受光照或反光影响偶发漏检，使用官方评测数据集黄金测试视频段（`7段评测集`），确保 `tl_det` 100% 检出率与准确决策。

### 镜头 6：赛题测试 (2) 虚实线变道合规监控 (01:49 - 02:14, 25s)
- **画面内容**：
  - 车辆行驶于多车道干道，左侧为白色虚线，右侧为连续双黄实线。
  - 驾驶员发出左转信号：屏幕左下角立即打出绿色通行箭头，决策引擎判定为合规变道（ALLOW）。

  - 驾驶员长按按键强行压实线变道：系统即刻判定违规压线，右侧箭头变为亮红，伴随红色闪烁边框报警（ALARM）。
- **屏幕叠加字幕**：
  - 行1：虚线变道放行 实线禁行拦截
  - 行2：强制压实线变道即刻触发告警
- **物理操作**：
  - 01:52：行至虚线段，短按 KEY2（B22，约 0.2 秒），触发左转向变道请求。
  - 01:59：驶入实线段，短按 KEY3（A22，约 0.2 秒），触发右转向变道请求。
  - 02:05：长按 KEY3（约 1.5 秒），强制注入右变道压线指令。
- **解说词**：车道线检测核实时感知标线物理属性。虚线区段允许自如变道，而实线强行变道将瞬间触发压线红色警告。
- **拍摄方式**：HDMI 采集卡直录。
- **失败预案**：若道路光影干扰导致局部线型置信度抖动，在测试脚本中微调地面消失点参数或选取标线清晰的标准测试片段，保证虚线与实线状态机严格翻转。

## 三、录制前物理与电气检查清单（严格 18 条）

> 必须在开机录制前按序逐一核对打勾，任何一项不满足严禁开机拍摄。

- [ ] **1. 板卡机械紧固**：盘古 100Pro+ 与 OK3568 底板间的双螺柱必须完全拧紧定位，严防晃动。
- [ ] **2. P29 插槽金手指防护**：确认卡已垂直插到底，**严禁在通电状态下触碰、扳动 P29 插槽或插拔板卡**。
- [ ] **3. 供电树独立隔离**：FPGA 必须使用独立 12V 适配器供电，RK3568 使用原装 12V 适配器，地线可靠共地。
- [ ] **4. 开机上电时序**：严格执行「**先开 FPGA 电源加载固件，后开 RK3568 电源启动系统**」原则。
- [ ] **5. FPGA Flash 固件版本确认**：串口读取 `0x838` 寄存器值应为 `0x20261101`（cam18 提交位流；若 Flash 暂为 cam17 则为 `0x20261029`）。
- [ ] **6. PCIe 链路速率检查**：进入系统执行 `lspci -vvv`，确认链路状态锁定在 `5.0 GT/s, width x2`（Gen2 x2）。
- [ ] **7. U 盘物理格式与分区**：U 盘格式化为标准 FAT32，卷标为纯英文，插入 RK3568 USB 3.0 高速口。
- [ ] **8. U 盘演示测试素材齐备**：根目录下放置 `test_1.mp4`、`test_2.mp4`、`test_3.mp4`、`test_4.mp4`（1080P/720P H.264 基线编码）及中文命名测试文件各一份。
- [ ] **9. 三路 USB 摄像头连通性**：插入指定 USB 口，通过 `ls /dev/video*` 确认识别出 3 组视频节点且镜头保护膜已撕除。
- [ ] **10. 镜头采光与反光控制**：摄像头前视测试车道模型摆放平整，避免现场顶灯直接照射引发过曝反光。
- [ ] **11. HDMI 信号传输稳定性**：使用高屏蔽 HDMI 2.0 线缆连接盘古开发板 HDMI TX 口至视频采集卡。
- [ ] **12. HDMI 采集卡参数锁死**：采集卡 EDID 设置为固定 1920×1080@60Hz，严禁开启自适应缩放或 HDR。
- [ ] **13. OBS 录制参数校验**：录制分辨率严格为 1920×1080，帧率锁定 60 fps，编码器设为 NVENC 或 CPU H.264，码率锁定 12 Mbps CBR，音频采样率 48 kHz。
- [ ] **14. 颜色空间与范围**：采集软件中配置视频格式为 NV12 或 YUY2，色彩空间 BT.709，色彩范围 Full。
- [ ] **15. 实体按键响应测试**：开机前测试 KEY0–KEY4 机械弹性，消抖电平切换正常，无连键粘连。
- [ ] **16. 录制脚本与按键序列张贴**：将按键操作时间表打印并贴在录制机位旁，确保按键人与录屏人读秒同步。
- [ ] **17. 辅助机位手机参数设置**：副机位手机固定于三脚架，开启 4K 60fps 模式，锁定曝光与对焦（AE/AF LOCK）。
- [ ] **18. 静电与现场环境**：录制人员佩戴防静电手环，桌面远离大功率射频或电机干扰源。

## 五、后期剪辑合成与音画包装规范

### 1. 视频画质与编码标准
- **分辨率**：标准 1080P（1920 × 1080 逐行扫描，宽高比 16:9）。
- **编码格式**：H.264 / AVC（High Profile, Level 4.2），封装格式 MP4。
- **视频码率**：动态码率 VBR 8–12 Mbps（目标码率 10 Mbps，峰值码率 15 Mbps）。
- **帧率**：严格 60.00 fps（不得使用可变帧率 VFR）。
- **像素格式**：YUV 4:2:0（8-bit）。

### 2. 字幕排版与视觉标识规范
- **中文字体**：思源黑体（Source Han Sans CN Bold）或 微软雅黑 Bold。
- **英文字体**：DIN Alternate Bold 或 Arial Bold。
- **主标题字号**：42 pt，纯白（#FFFFFF），加 2 像素 40% 黑色投影（平滑柔和）。
- **正文字幕字号**：32 pt，文字居中，行宽限制在 **18 个汉字以内**，底部边距 80 像素。
- **数据标注卡与高亮字**：高亮重点数据使用竞赛青色（#00E5FF）或琥珀金（#FFB300）。

### 3. 音频设计与旁白要求
- **音频轨配置**：立体声双声道（Stereo），采样率 48 kHz，AAC-LC 编码，码率 256 kbps。
- **配音旁白**：录音棚级清晰解说，男中音或女声沉稳专业，解说音量电平控制在 **-6 dB 至 -3 dB** 之间，去底噪、压限处理。
- **背景音乐 (BGM)**：选用科技感、快节奏、具有前进动力的轻度电子音乐（如 Tech Minimal / Deep Ambient）；BGM 音量必须全程压低至 **-20 dB 至 -24 dB**，严禁掩盖人声。
- **音效提示**：在告警边框爆闪（01:32、02:08）瞬间，叠加短促微弱的雷达警示音效（Buzzer SFX）。

### 4. 镜头转场与时间轴纪律
- **转场方式**：以硬切（Cut）为主，部分模块过渡使用极速交叉溶解（Cross Dissolve，不超过 0.3 秒），杜绝炫目三维翻转特效。
- **严守时限**：成片绝对时长控制在 **02:54:00**（误差不得超出 ±0.5 秒），严禁突破 03:00 比赛红线。

## 六、功能边界与明确禁录声明

> 依据比赛命题要求与现有工程真实已验证记录，以下内容**严禁出现在演示视频中**：

1. **导航功能规范（路线文件驱动）**：
   - 现状：当前导航变道决策基于 `.nav` 路线引导文件（模拟导航模块输出）驱动，中控屏小地图图标视觉解析与全局路径规划尚未部署。
   - 规范：导航只允许以“模拟导航文件（路线文件驱动）”的名义出现，禁止说成真实导航/小地图识别/路径规划；解说词不得提倡未开发功能。
2. **绝对禁录物理刹车执行器控制**：
   - 现状：系统决策通过寄存器 `0x850` 完成亚毫秒级声光告警与屏幕警示，未连接实际底盘线控刹车电机。
   - 规范：不得宣称「已实现物理线控刹车制动」，一律统一口径为「车道级声光安全预警与制动提示」。
3. **审慎对待斑马线硬件核**：
   - 现状：`rt_zebra` 硬件加速核目前板上测试存在微小稳定性抖动，正在工程优化中。
   - 规范：仅在四路实时菜单中作为调试视图展示一次，解说词不作展开，若拍摄时偶发异常则直接移出镜头，严禁当作主打成熟功能宣传。
4. **诚实注明检测输入源**：
   - 针对行人与复杂障碍物检测，若使用本地录制测试视频流验证 NPU，必须在字幕中明确标注「测试样本回放测试」，体现严谨求实的工程素养。
