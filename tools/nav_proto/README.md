# 车载中控导航动作识别原型 (Nav Proto)

## 1. 算法流程
1. **真值加载**：解析 `video_review/gt/112739_timeline.csv` 中的 `nav_maneuver` 转向事件（共 15 条：8 次 right、5 次 left、2 次 uturn，straight 为 0 条不参与评测）。
2. **ROI 裁剪**：对视频每一真值时刻帧提取中控屏所在的左下象限（$x \in [80, 750], y \in [560, 1080]$，尺寸 $670 \times 520$）。
3. **NCC 模板匹配**：使用 OpenCV 归一化互相关匹配（`cv2.TM_CCOEFF_NORMED`）分别比对各动作模板，获取最大响应分值与空间坐标。
4. **置信度门限**：设定固定先验阈值 0.50，最高分值 $< 0.50$ 判定为 `unknown`，否则输出 argmax 类别与全局坐标。

## 2. 模板来源与防泄漏说明
所有模板均手工截取自视频中**非评测时刻**，严格独立于评测时间戳集合，杜绝数据泄露：
- `right`：截取自 $t=6.0$ s（非 GT，介于 2.0 s 与 10.0 s 之间），保存为 `arrow_right_6s.jpg`；
- `left`：截取自 $t=55.0$ s（非 GT，介于 54.0 s 与 58.0 s 之间），保存为 `arrow_left_55s.jpg`；
- `uturn`：截取自 $t=87.0$ s（非 GT，介于 84.0 s 与 90.0 s 之间），保存为 `arrow_uturn_87s.jpg`；
- `straight`：真值中无对应事件，未硬造模板，不参与评测。

## 4. 失败主因分析
1. **手持机位剧烈平移与尺度缩放**：车载拍摄由手持设备记录，中控屏坐标在全视频中大幅漂移（横向偏移超 230 像素，纵向偏移超 100 像素）。大范围象限搜索导致模板频频虚警于座椅缝线与出风口等内饰纹理（如 20s/30s 将 right 误判为 left）。
2. **转向与路口动态曝光/强光反光**：车辆在 $t=38 \sim 46$ s 右转过程中，车身侧向迎光导致中控玻璃屏严重反光，箭头局部对比度下降，造成相关系数骤降。
3. **导航车道级 UI 动态变构**：在 $36$ s 和 $58$ s 临近路口时，导航卡片自动拉起车道指示图，卡片底色与尺寸突变，纯静态模板丧失特征泛化能力。

## 5. 板端部署方案设计 [未上板]
为解决纯视觉模板在复杂车载场景鲁棒性低与计算瓶颈问题，建议板端采用如下异构流线（未实际烧录与上板验证）：
- **FPGA 前端预处理**：1080p@30fps 输入流经 FPGA 进行可编程 ROI 硬件裁剪与灰度降采样（输出 $128 \times 128$ 屏幕焦点区域），消除内饰杂散区域与总线带宽压力。
- **RK3568 NPU 分类替代纯 C 模板**：
  - *纯 C 模板复杂度*：在 $670 \times 520$ 象限内滑窗匹配 3 个模板约需 4.37 GFLOPS/帧，单 CPU 软解无法满足 30 fps 实时要求；
  - *NPU 轻量模型*：采用 MobileNetV3-Small 或微型 CNN（分类头 4 类），输入 $64 \times 64$ 分辨率，INT8 模型仅约 0.8 MB，RK3568 单次推理耗时 $<2$ ms，算力消耗仅约 5 MFLOPS（占用 NPU 算力 $<1\%$），且具备尺度和光照不变性。
