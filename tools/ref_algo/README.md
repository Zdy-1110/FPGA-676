# 参考算法与离线评测

用 Python 实现认灯、认线、自车运动、判决，再用层 A 真值和测试用例做离线评测。这些算法以后要移植到 FPGA，所以只用逐像素阈值、小核形态学、连通域、直线拟合这类能映射到硬件的操作。阈值全部集中在 `params.json` 里。

## 文件

| 文件 | 作用 |
|---|---|
| `params.json` | 全部阈值（按调参结果设定） |
| `video_io.py` | 通过 ffmpeg 管道解码，按 step 抽帧 |
| `tl_ref.py` | 认灯：颜色掩膜 → 过曝补洞 → 连通域 → 灯面亮度、中心填充、灯箱侧暗检验 → 形状（圆 / 左 / 直 / 右）→ 车道关联 → 多帧滤波（停车时保持） |
| `lane_ref.py` | 认线：消失点自动标定（可人工指定）→ 局部亮度突起找标线 → 霍夫直线 → 左右边界 → 1 s 时间窗内按覆盖率判断虚实 |
| `motion_ref.py` | 自车运动：相位相关补偿晃动后做帧差，5 帧中值，滞回判断 |
| `decide_ref.py` | 判决：信号灯（GO / STOP / ALARM）、变道（ALLOW / KEEP / ALARM）、LED 位 |
| `run_ref.py` / `run_all.py` | 处理单段 / 全部视频，输出 `states.csv`、`calib.json`、叠加快照（可选叠加视频） |
| `eval_ref.py` | 逐帧状态准确率，以及 SIG / LANE 测试用例通过率 |
| `oracle_states.py` | 用真值构造理想感知，检验判决规则与用例生成器的口径是否一致（101/101 通过） |

## 运行

```bash
.venv_yolo/Scripts/python.exe tools/ref_algo/run_all.py --out video_review/ref_runs/A2_auto
.venv_yolo/Scripts/python.exe tools/ref_algo/eval_ref.py --runs-dir video_review/ref_runs/A2_auto --out-md video_review/ref_runs/A2_auto_eval.md --out-csv video_review/ref_runs/A2_auto_cases.csv
```

人工指定车道线区域和消失点：给 `run_ref.py` 传 `--roi y_top,y_bot,vp_x,vp_y`。

7 段视频共 2678 个处理帧（每 3 帧取 1 帧），全部跑完约 2.8 分钟；每帧耗时约 50–60 ms，其中认灯约 30 ms。

## 车道线 v2：鸟瞰图（`lane_bev.py`，现为默认 `lane.method="bev"`）

流程：
1. 按消失点（VP）建单应矩阵，把整帧变换到 400×400 鸟瞰图。顶行取在 VP 以下路面高度 30% 处，这样 VP 有 ±40 px 误差也不至于把远处拉坏。
2. 在鸟瞰图里提取脊线：像素要比左右各隔 6 px 处都亮出 18。宽的亮区（车身）在 ±6 px 处仍然亮，会被排除。再按颜色分成白线和黄线。
3. 用整幅高度的列直方图找起点，取离自车最近的局部极大值。跟踪状态下，如果出现明显更近的候选线，就切换过去。
4. 10 个滑窗逐段跟踪，然后直线拟合。
5. 判断虚实：沿拟合线统计最长连续占用段，达到高度的 45% 判为实线（实线远段被车挡住时仍有长连续段）。再按 1 s 时间窗多数表决；黄线占比、双峰用来判断颜色和双黄线。
6. 消失点自校正：用左右两条自车车道线在原图里的交点，慢慢修正消失点。
7. 叠加图右上角附鸟瞰调试小窗。

车道线模块每帧约 3 ms（霍夫法约 17 ms）。

| 方案（全部为自动标定） | 车道线逐帧类型一致率 | LANE 用例 |
|---|---|---|
| 霍夫法 v1（A2_auto） | 46.4% | 9/32 |
| 鸟瞰图，判据为最长连续段 ≥ 35%，只用下半幅直方图（C_bev_auto） | 40.3% | 21/32 |
| 鸟瞰图，判据为 ≥ 45%，整幅直方图，可切换到更近的线（E_r45，当前默认） | 65.3% | 17/32 |

E_r45 的 SIG+LANE 合计为 80/101。人工标定反而更差：人工初值加自校正只有 37.5%，因为人工估的消失点误差比自动标定还大。

剩余错误主要有三类：
- 自车车道选错。手机拿在驾驶员手里，镜头中心几乎正对着自车的左边界线（113539 的双黄线、113343 靠护栏的黄线），算法容易挑到更左边的线。单纯把自车位置往右挪（0.55W、0.60W）整体反而变差。需要改成"左右成对选线，并用车道宽度约束"。
- 遮挡和路口段：被车挡住、斑马线、路口内没有标线。
- 真值本身有误：例如 112507 在 12 s 时车已经开上斑马线，真值仍标为实线。

## 车道线 v3：成对选线（`bev.pair_mode=true`，现为默认）

做法：
1. 在鸟瞰图列直方图里取最多 12 个候选峰，枚举所有 (左, 右) 组合。
2. 硬约束：间距在鸟瞰图宽度的 12%–40% 之间；镜头在车道内的相对位置 p 在 [-0.1, 0.85] 之间。
3. 打分：两线强度（开平方）、间距与已学车道宽度是否一致、p 与已学值是否一致、与上一帧选中的线对是否接近。
4. 车道宽度和 p 都按视频在线学习（EMA）。
5. 找不到合格的线对时，退回逐侧找线。
6. 消失点自校正只允许在初始标定值附近浮动：x 方向 ±12%W，y 方向 ±6%H。
7. 每帧的候选和选择结果写入 `lane_debug.csv`。

| 方案（自动标定） | 车道线逐帧一致率 | LANE 用例 | 112507 逐帧 |
|---|---|---|---|
| 逐侧找线（E_r45） | 65.3% | 17/32 | 74% |
| 成对选线，消失点自校正不限幅（G_pair） | 72.2% | 18/32 | 86.6% |
| 成对选线，消失点自校正限幅（H_pair，当前默认） | 71.2% | 17/32 | 86.6% |

默认选 H 而不是 G：G 在 113539 的 40 s 处，消失点被错误线对一路拉到 (930, 282)，鸟瞰图完全失效。限幅牺牲了约 1 个百分点，换来不失控。

剩余问题：
- 113343：自动标定的消失点是 (632, 576)，实际约在 (900, 755)，错得太远，自校正的限幅范围内够不到真值，属于上游标定问题。可在鸟瞰图里搜索消失点：取一组候选消失点，看哪个能让累积的脊线最"竖直"、列峰最尖锐。另外这段的真值也可疑：从画面看，车更可能在中间车道，左线是白虚线而不是护栏边的黄实线。
- 113539 在 37–47 s：车在越过双黄线超车，双黄线落在镜头右侧，这段真值本身有歧义。双黄线和黄、白颜色的判断也需要专门检查。

## 消失点自动标定的尝试（均未采用，默认仍为 `bev.vp_search=false`）

| 方法 | 做法 | 结果 |
|---|---|---|
| 霍夫线段投票（现用） | 标线线段两两求交点并投票 | 113343、113421、113452 偏 100–300 px，因为地平线以上的线段太多 |
| 扩展焦点（FOE）原型 | 光流按各向同性放大模型拟合，加权中位数 | y 较准（112507 误差 <10 px，113452 约 0）；x 受转向和手持偏航影响，113539 偏 430 px，113343 偏 280 px |
| 鸟瞰图竖直度（`vps_mode="verticality"`） | 固定近处路面带，列直方图越尖锐得分越高 | 参考消失点的得分比选中的错误点还低，指标本身没有区分力 |
| 闭环搜索（`vps_mode="closed_loop"`） | 每个候选消失点完整跑一遍成对选线，看两条线是否都找到、斜率是否小 | 几乎每个候选都能找到一对线；斜率项随候选改变路面带而被扭曲，偏向画面偏上的点。参考点得分也更低 |

共同的根因：路面带下沿 y_bot 常常压到仪表台上，候选消失点又会改变鸟瞰图覆盖的区域，两者都让打分失真。代码保留在 `lane_bev.py`，便于以后接着做。

## 按键标定的离线模拟

- `vp_measure.py`：在两条自车车道线都拟合良好的帧上求两线交点，取中位数后迭代，测出每段视频的 VP。输出 `video_review/vp_measure/<id>/`，内含核对图 `vpm_sheet.jpg`。
- 用测得的 VP 代替自动 VP、保留限幅自校正。要点：
  - y_bot 要尽量低；
  - 在当前真值下，准确 VP 的成绩与自动标定持平，为 J_cal 的 70.1%、17/32；
  - 113343 用准确 VP 反而更差，提示该段真值可能有误。
- 运行方式：`run_ref.py --roi y_top,y_bot,vp_x,vp_y`。默认参数 `bev.refine_after_manual=true`，即人工值只作初值，之后照常限幅自校正。

## 已知问题

1. 车道线是短板（v1 霍夫法时的分析，v2、v3 见上两节）。
   - 自动消失点标定只有 113539 准确，其余几段偏差约 ±100 px。
   - 改成人工标定后结果也没有变好（21.9%），说明问题不只在标定。
   - 霍夫直线加候选挑选的方法，在路边停满车、标线杂乱的城市道路上经常挑错线。实线几乎检不出来：真值为实线的 480 帧里只有 19 帧判对。
   - 改为：按消失点逆透视到鸟瞰图 → 在自车位置附近找列向峰值 → 滑窗跟踪 → 沿线统计断开比例判断虚实。
2. 车道线真值也需要核对。
   - 112507 在 9.5–12.5 s：12 s 时车已经开上斑马线，画面里没有自车车道线；
   - 113539 在 37–47 s 和 54–60 s：双黄线在画面里的位置和方向都存疑。
3. 认灯误检：限速牌红圈、行人灯、远处的小块黄色物体都曾被当成灯。已分别用中心填充检验、宽高比限制、最小尺寸 8 px 压掉。将来补夜间、逆光素材后需要重新调参。
4. 112739 镜头朝下，路面只占 0.47H–0.55H 这一窄条；它的信号灯真值是从导航地图推断的，参考价值有限。
