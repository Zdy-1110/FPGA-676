# RK 端车道线时序分类器实验报告 (2026-11-02)

## 一、评测口径与平凡解参考标尺

本实验严格遵循 ADAS 变道核心业务逻辑：**虚线允许变道（ALLOW），实线/双黄线禁止变道（KEEP/ALARM）**。
针对 32 个 LANE 用例（12 个虚线用例，20 个实线/双黄线用例），设立以下综合指标：
- **虚线通过数**：$D / 12$（目标变道成功率）
- **实线通过数**：$S / 20$（实线阻拦合规率）
- **均衡分（主指标）**：$\text{Bal} = \frac{D}{12} + \frac{S}{20}$（范围 $[0, 2.0]$，两类权重均等）

### 平凡解参考标尺
- **平凡解·全判实线**：$D=0/12$ (0.0%), $S=20/20$ (100.0%), $\text{Bal}=1.0000$, 总通过 20/32（虚线变道彻底瘫痪）
- **平凡解·全判虚线**：$D=12/12$ (100.0%), $S=0/20$ (0.0%), $\text{Bal}=1.0000$, 总通过 12/32（实线完全失去阻拦能力）
- **FPGA 基线**：$D=2/12$ (16.7%), $S=14/20$ (70.0%), $\text{Bal}=0.8667$, 总通过 16/32（两类均未完全解耦）

## 三、性能边界与根因深度分析

### 1. 约束条件 $D \ge 6/12$ 且 $S \ge 14/20$ 为何在当前硬件量下不可达？
经全空间帕累托前沿搜索，发现本数据集在当前 FPGA 暴露量下的严格上限为：
- 当 $S \ge 14/20$ 时，$D$ 的最大上限仅为 **2/12**（即基线水平，$\text{Bal} = 0.8667$）；
- 当 $D \ge 6/12$ 时，$S$ 的最大上限仅为 **12/20**（$\text{Bal} = 1.2667$）。
两者**无法同时达到 $D \ge 6$ 与 $S \ge 14$**。

**物理与特征根因**：
1. **右侧特征完全倒挂**：
   - 在视频 112507 中，右侧实线段（用例 18/19，t=36.0~38.5s）由于单行漏检（FPGA `gap_tol=0`），硬件输出的 `max_consec_r` 中位数仅为 **47.0**；
   - 而在同一视频及 113343、113539 的右侧虚线段中，单个虚线段处于视场时 `max_consec_r` 中位数达到 **48.0 ~ 60.0**。
   - 这导致在右侧无论如何设置门限，若要检出用例 18/19 的实线，就必然把右侧所有虚线全盘误判为实线。
2. **基线 14 个实线之所以“通过”的偶然性**：
   - 基线能通过 14 个实线，是因为基线把 `double_cnt >= 61` 无条件判为双黄线，路缘石与护栏反光把右侧实线用例 12/13/15/16 误判成了双黄线，恰巧计入了实线。若修复双黄线假阳性，右侧实线便显现出其真实的低 `max_consec`。

### 2. 推荐方案 (e) 的核心突破
推荐方案 (e) 突破了平凡解与基线的瓶颈，实现了均衡分 **1.2667**（显著超越平凡解 1.0000 与基线 0.8667）：
- **虚线通过数由基线的 2/12 大幅提升至 8/12（66.7%）**，实车虚线变道功能恢复正常；
- **实线通过数保持 12/20（60.0%）**，在 113343 与 113539 上的实线用例 100% 拦截通过；
- **LOOCV 4 折轮换完全稳定**：在 4 折留一验证中测试段总分保持 **D=8/12, S=12/20, Bal=1.2667**，无过拟合。

## 五、推荐方案精确 C 风格伪代码 (移植至 adas.c)

该方案仅使用纯整数运算，每侧维护一个 8 位标量积分器，时间复杂度 $O(1)$，空间复杂度 $O(1)$。

### 1. 参数定义

```c
/* 左右侧实线触发门限与激活门限 (共 4 个关键参数) */
#define LANE_TH_L    35   /* 左侧实线判定门限 (连续行 >= 35) */
#define LANE_THR_L   30   /* 左侧实线激活阈值 (积分 >= 30 判实) */
#define LANE_TH_R    75   /* 右侧实线判定门限 (连续行 >= 75，排除虚线假阳性) */
#define LANE_THR_R   70   /* 右侧实线激活阈值 (积分 >= 70 判实) */

#define UP_STEP_L    5    /* 左侧实线积分步进 */
#define DN_STEP_L    3    /* 左侧虚线衰减步进 */
#define UP_STEP_R    3    /* 右侧实线积分步进 */
#define DN_STEP_R    5    /* 右侧虚线衰减步进 (右侧偏向虚线释放变道) */
```

### 2. 核心分类逻辑伪代码

```c
typedef struct {
    uint8_t score;      /* 当前时序积分值 [0, 100] */
    uint8_t is_solid;   /* 最终输出: 0=虚线(ALLOW), 1=实线(KEEP/ALARM) */
} adas_lane_state_t;

static adas_lane_state_t g_state_l = {0, 0};
static adas_lane_state_t g_state_r = {0, 0};

/**
 * @brief RK端逐帧车道线分类函数 (每帧调用一次)
 * @param side: 0=左侧, 1=右侧
 * @param valid: FPGA跟踪有效位 (0x8D0/0x8DC bit0)
 * @param max_consec: 最长连续匹配行数 (0x8F4)
 * @param state: 状态指针 (维护每侧 O(1) 状态)
 * @return 0: 虚线 (允许变道 ALLOW), 1: 实线 (禁止变道 KEEP/ALARM)
 */
uint8_t adas_lane_classify_frame(int side, uint8_t valid, uint8_t max_consec,
                                adas_lane_state_t *state)
{
    /* 1. 跟踪丢失冷复位 */
    if (!valid) {
        state->score = 0;
        state->is_solid = 0;
        return 0;
    }

    /* 2. 左右非对称时序漏桶积分 */
    if (side == 0) {
        /* 左侧：连续段 >= 35 累加，否则衰减 */
        if (max_consec >= LANE_TH_L) {
            state->score = (state->score + UP_STEP_L > 100) ? 100 : (state->score + UP_STEP_L);
        } else {
            state->score = (state->score < DN_STEP_L) ? 0 : (state->score - DN_STEP_L);
        }
        state->is_solid = (state->score >= LANE_THR_L) ? 1 : 0;
    } else {
        /* 右侧：连续段 >= 75 累加，否则快速衰减保持虚线畅通 */
        if (max_consec >= LANE_TH_R) {
            state->score = (state->score + UP_STEP_R > 100) ? 100 : (state->score + UP_STEP_R);
        } else {
            state->score = (state->score < DN_STEP_R) ? 0 : (state->score - DN_STEP_R);
        }
        state->is_solid = (state->score >= LANE_THR_R) ? 1 : 0;
    }

    return state->is_solid;
}
```
