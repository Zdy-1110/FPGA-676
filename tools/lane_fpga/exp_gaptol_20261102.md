## 三、RTL 改动量估算与时序影响分析

### 1. 定位 rt_lane_det.v 计数逻辑行号
- **计数寄存器定义**：`fpga/src/disp/rt_lane_det.v:524-526` (`cur_consec_l`, `max_consec_l`, `double_cnt_l`)
- **复位与帧起始清零**：`rt_lane_det.v:551-556` (全局复位) 与 `rt_lane_det.v:586-591` (帧起始 `vsync` 下降沿清零)
- **逐行连续计数与更新**：`rt_lane_det.v:654-661` (左侧) 及 `rt_lane_det.v:671-678` (右侧)
- **帧末实虚分类判决**：`rt_lane_det.v:1156-1161` (比较 `max_consec >= solid_rows_eff` 与 `double_cnt >= dbl_rows_eff`)
- **缺省门限参数定义**：`rt_lane_det.v:37-38` (`DEF_SOLID_ROWS = 8'd61`, `DEF_DBL_ROWS = 8'd61`)

### 2. gap_tol 新增硬件资源与位宽估算
- **寄存器位宽**：新增左/右未命中连续间隔计数器 `reg [3:0] cur_gap_l, cur_gap_r;`（支持 G 最大为 15，此处 G=4~6，仅需 4 bit）。若双黄同时应用，新增 `reg [3:0] cur_gap_dbl_l, cur_gap_dbl_r;` 及 `reg [7:0] cur_consec_dbl_l, max_consec_dbl_l;`。
- **比较器与加法器**：
  - 4-bit 比较器：`cur_gap_l >= GAP_TOL`（仅 4 LUT）
  - 4-bit 加法器：`cur_gap_l + 4'd1`（仅 4 LUT）
  - 总新增资源：触发器 (FF) 约 8~24 个，LUT 约 16~32 个，占整个 FPGA 资源 < 0.1%。

### 3. 对 148.5 MHz 时序关键路径的影响评估
- **关键路径分析**：连续计数逻辑处于 `lb_fsm == 3'd2`（行后处理状态）。该状态与行显示并行，处于行消隐期（H-Blanking）。
- 同一状态内的现有路径为 18x18 乘法加法器（`acc_sxx_l <= acc_sxx_l + best_x_l * best_x_l`），组合逻辑延迟约 3.5 ns。
- 新增的 4-bit 计数与比较逻辑仅有 1 级门延时（< 0.3 ns），完全不属于关键路径。
- **结论**：**对 148.5 MHz 时序零负面影响，时序裕量（Slack）充足**。

### 4. RTL 改动伪代码
```verilog
// 1. 定义断行容差参数与 gap 计数器 (rt_lane_det.v:524 附近)
localparam [3:0] GAP_TOL = 4'd6; // 推荐 G=6 (或 G=4)
reg [3:0] cur_gap_l, cur_gap_r;

// 2. 帧起始清零 (rt_lane_det.v:586 附近)
cur_gap_l <= 4'd0;
cur_gap_r <= 4'd0;

// 3. 行末累加时带 gap_tol 的连续计数 (替换 rt_lane_det.v:656-661)
if (l_found) begin
    cur_gap_l    <= 4'd0;
    cur_consec_l <= cur_consec_l + 8'd1;
    if (cur_consec_l + 8'd1 > max_consec_l)
        max_consec_l <= cur_consec_l + 8'd1;
end else begin
    if (cur_gap_l >= GAP_TOL) begin
        cur_consec_l <= 8'd0;
        cur_gap_l    <= 4'd0;
    end else begin
        cur_gap_l    <= cur_gap_l + 4'd1;
    end
end
```

## 四、今晚是否修改 RTL 的工程建议

1. **收益评估**：
   - 改用 `gap_tol=6, solid_rows=61` 可使 LANE 用例通过数由 **16/32 提升至 18/32**（+2 用例，实线漏检 s2d 错由 6 骤降为 2），在 4 折交叉验证中测试段通过总数达 18/32。
   - 若改用 `gap_tol=6, solid_rows=97` 配合双黄连续抑制（Rule D），总通过数达到 **17/32**，实/虚比例为均衡的 71.7%/28.3%。
2. **风险评估**：
   - **时序与资源风险为零**：仅需约 8 个 FF 与 16 个 LUT，时序延迟极小。
   - **过拟合/虚线误判风险**：G=6 门限保持 61 时，全视频实线比例上升至 85.4%，虚→实误报警略有增加（10 -> 12）。
3. **最终结论**：
   - **若追求今晚 PDS 到期前冲刺最高分**：**建议修改**。采用 G=6（改动代码仅 15 行），预计通过数由 16 提升至 18，实线检出率明显提高，风险极低。
   - **若追求稳健均衡与行车变道容错**：**建议维持 baseline 或微调为 G=4+sr=97**，避免单虚线被过多连续桥接。
